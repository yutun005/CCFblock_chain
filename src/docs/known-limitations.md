# 已知限制与未实现项

| 项目 | 状态与影响 |
|---|---|
| 恶意授权验证者 | P0 无法识别业务语义真假；SEC-30 可支付错误结果，明确 LIMITATION |
| A2A 服务端点身份绑定 | 属于 B；SEC-09 未完成跨模块验收 |
| 虚假服务能力/完整成果验证 | 属于 A/B；SEC-10 未完成跨模块验收；C 提供确定性统计规则夹具 |
| 全平台正常/故障端到端 | 当前是 C 的真实链集成；不冒充 A2A 调度和市场完成 |
| 双验证者、争议期 | P1 未实现 |
| 旅游业务场景 | P1，由 A/B 提供配置与业务 Agent 后联调；结算内核不含领域分支 |
| token 兼容性 | 仅固定标准测试 ERC-20；不支持手续费、重基准、任意恶意 token |
| Solidity 合约升级 | 无代理，无可升级合约；接口变化需重新部署并更新签名域 |
| 高可用交易服务 | 当前同一主机同一账户文件锁；跨主机发送同一账户需集中队列 |
| 数据库部署 | C 的本地交易日志是 SQLite；团队 PostgreSQL 业务数据库由集成层接入 |
| 多组织部署 | 五容器均在本机，不代表真实独立组织运维 |
| 测试时间跳跃 | Besu 不提供 Anvil 时间 RPC，精确边界用 Foundry/Anvil；Besu 等待真实时限 |
| 财务真实性 | 测试单位无真实价值，无真实支付系统或商业上线证明 |
| Git 发布 | 模块交付含源码校验清单；最终团队 Git commit/tag 由 D 合并发布 |

发现并修复的测试/集成问题见 `docs/测试报告.md`。实际执行结果以 `experiments/raw/` 为准，SKIP 不计入 PASS。
