# 部署与使用说明

系统架构和协议边界见[设计报告](设计报告.md)，验证结果见[测试报告](测试报告.md)。

## 从干净环境复现

在 Windows PowerShell 或 Linux/macOS 终端克隆 Dmodule 分支，并进入仓库根目录：

```powershell
git clone --branch Dmodule --single-branch https://github.com/yutun005/CCFblock_chain.git
cd CCFblock_chain
python --version
node --version
pnpm --version
python manage.py setup
```

使用 Python 3.12、Node.js 24、pnpm 11.25.0 和 Foundry 1.8.5。`setup` 安装锁定的 Python、Web 与合约依赖并构建 Web 产物。完整安装需要访问依赖源；首次运行后先执行[复现与检查](#复现与检查)中的命令。

## 容器化验证入口

有 Docker Compose v2 的电脑可在克隆的仓库根目录执行：

```powershell
$env:AGENTFLOW_SOURCE_COMMIT_SHA = (git rev-parse HEAD)
docker compose run --build --rm verify
```

`Dockerfile` 使用 Python 3.12、Node.js 24、pnpm 11.25.0、仓库锁定的 Foundry/依赖和 Playwright Chromium 构建 `linux/amd64` 环境。`verify` 在容器内运行合约测试、一次真实浏览器加 API 正常/恢复流程、一次旅游场景和结果汇总；原始记录及汇总挂载回主机的 `experiments/`。设置提交 SHA 后，容器内无 `.git` 也能把版本写进原始结果；未设置时会标为 `unversioned-container`。这条命令不执行主场景 10 次重复批次，完整重复验收仍按下文命令进行。当前本机未安装 Docker，**该容器入口尚未实际运行**；配置存在不等于干净环境复现通过。

## 本机准备

当前应用使用外部提供的 EVM RPC、6 位小数测试 ERC-20 和 C 接口的 DASC `TaskEscrow`。该仓库的启动器会安装并构建应用，但目前不会自行创建 Anvil、部署合约或生成钱包；部署前需由团队提供本地开发链地址、合约地址和隔离测试账户。

软件版本以仓库锁定文件为准：Python 3.12、Node.js 24、pnpm 11.25.0、Foundry 1.8.5、Solidity 0.8.28。Windows 可在 PowerShell 中从仓库根目录执行：

```powershell
python manage.py setup
python -m unittest discover -s tests -v
```

首次安装需要访问 Python、Foundry、OpenZeppelin 和 pnpm 依赖源。若当前 `python` 不是 3.12，请先安装 Python 3.12 并用它执行 `manage.py setup`。

## 合约与账户

使用 C 的 `TaskEscrow.sol` 部署：构造参数为测试 ERC-20 地址和管理员钱包地址。部署者向验证者授予 `VERIFIER_ROLE`。所有角色必须使用独立账户；只允许无真实价值、无转账手续费的本地测试代币。

编辑被忽略的 `runtime.json`，结构参照根目录 `project.json` 的 `runtime` 区域。配置 RPC、chainId、代币地址、合约地址、各服务端点和环境变量名称；在 PowerShell 环境变量或 IDE 运行配置中填写各角色私钥及至少 32 字符的 API token。不要把密钥、钱包文件或真实业务资料提交到 Git。

按顺序完成绑定和授权：

```powershell
python manage.py configure --config runtime.json
python manage.py approve --amount 100 --config runtime.json
python manage.py start --config runtime.json
```

`configure` 验证 chainId、代币精度、合约代码、代币绑定和验证者角色；`approve` 由 owner 授予托管合约明确额度；`start` 启动市场、验证器、Agent、API 和 Web。应用启动后使用 `AGENTFLOW_API_TOKEN` 登录，按根目录 README 中的网页流程运行销售分析或旅游规划。

## 复现与检查

```powershell
python manage.py build
python -m unittest discover -s tests -v
pnpm --dir .cache/web exec playwright install chromium
pnpm --dir .cache/web run test:browser
python manage.py test-browser-live
python manage.py test-contract
python tests/e2e/run_main_scenario.py --repeat 10
python tests/e2e/run_main_scenario.py --scenario travel_planning --repeat 1
python manage.py collect-results
python manage.py archive-evidence
```

浏览器 smoke 会启动本地 Vite Web，并用 Playwright 路由 mock 检查登录、计划预览、创建任务请求和工作区渲染。`test-browser-live` 另启动临时 Anvil 与 6 个 A2A 服务，让真实浏览器创建一个任务、等待四节点完成，并核对页面资金事件的交易哈希与成果下载入口；同批次还运行 API 正常流程及超时恢复。Windows 若已安装 Chrome，可在命令前设置 `AGENTFLOW_BROWSER_EXECUTABLE` 指向 `chrome.exe`；CI 使用已安装的 Playwright Chromium。

截至报告记录的 `b6304fac01a405bd81fd4d229f753dea1eb99e4c`，GitHub Actions run [38871130279](https://github.com/yutun005/CCFblock_chain/actions/runs/38871130279) 已通过：主场景 10 次、旅游场景 1 次，实际 11/11 次 E2E PASS。原始日志和交易记录位于该 run 的 artifact `dmodule-verification-b6304fac01a405bd81fd4d229f753dea1eb99e4c`。旧 CSV 将批次与逐次结果重复计为 22 行，安全汇总也曾有函数名匹配缺陷；旧 artifact 未被改写，修正和本机重跑结果见测试报告。

E2E 脚本会为每次重复单独启动 Anvil、部署临时测试合约、启动 6 个 A2A 服务，并依次执行正常结算与超时恢复。每次原始结果和服务日志写入 `experiments/raw/e2e/<run-id>/`；批次的 `summary.json`、`summary.csv` 和逐次结果写入 `experiments/raw/e2e/batch-<batch-id>/`。至少 10 次运行由 `--repeat 10` 固定执行，任一次失败都会让脚本返回失败状态。

`test-contract` 将 Foundry 原始 JSON 同时映射到 `experiments/raw/security/SEC-01.json` 至 `SEC-30.json`；未实现或未运行的案例保留为 `SKIP`，SEC-30 明确标记为 `LIMITATION`。这些证据与 E2E 原始记录一起保存在 CI artifact 中。

`python manage.py run-data` 与 `run-travel` 分别复现两个场景；`test-e2e` 执行 10 次主场景；`test-security` 运行 Foundry 安全检查；`collect-results` 按唯一运行 ID 汇总原始数据，失败或无数据时返回非零退出码。`archive-evidence` 在 `.cache/delivery/` 生成原始证据 ZIP、逐文件哈希清单和 ZIP 的 `EVIDENCE-SHA256SUMS`；如果原始运行来自较早的提交，可用 `--run-commit <实验提交SHA>` 标注，分析提交仍取当前 HEAD。`reset-demo` 按所选 runtime 配置备份并重建缓存目录，备份放在 `.cache/demo-backups/`，不会接触缓存目录以外的数据或链上状态。

首次 setup 需要访问 Python、Foundry、OpenZeppelin 和 pnpm 依赖源；如果使用系统 Python，请先安装 Python 3.12。完整复现包含 Foundry 合约测试和本地 Anvil E2E。测试报告中的链上结论必须附交易回执和原始日志；ABI 单测与 Web 构建不代替链上测试或浏览器验收。运行结果应记录 commit SHA、chainId、合约地址、工具版本和数据输入哈希。
