# 部署与使用说明

## 首次安装

支持 Windows/Linux x64。安装 Python 3.13、Node 22、Git 和 `pnpm@11.25.0` 后，在包含整合代码的仓库根目录执行：

```shell
python manage.py setup
python manage.py dev
```

Linux 可用 `python3`。setup 在 `.cache/venv` 安装锁定的 Python 包，准备 Foundry 1.5.1，从固定提交和 SHA-256 归档安装 OpenZeppelin 5.2.0 与 forge-std 1.9.7，再安装前端依赖并编译。需要联网访问 PyPI、npm、GitHub 与 Solidity 编译器下载源；第三方环境不随 Git 提交。

Windows 已完成 setup 后，可双击根目录 `start-demo.cmd`。开发启动器首次创建测试账户并部署 MockUSDC/TaskEscrow；浏览器打开 **http://127.0.0.1:8080**，使用 `.cache/local-access.txt` 中的 token。

退出前台服务使用 Ctrl+C。停止本项目的本地链：`python scripts/local_demo.py stop-chain`。私钥、token、链数据库保存在忽略目录，每位使用者独立生成，勿复制公开发布。

## 使用流程

网页选择跨组织数据分析或旅游规划，预览输入、DAG 和预算后执行。页面提供市场报价、任务状态/SSE、成果下载、链上审计、报酬提现和用户退款。小型示例在 `data/`，端到端测试固定输入在 `tests/fixtures/`。

默认启动市场、独立验证器、6 个独立钱包的 Agent 和 API/Web。清洗/统计分别有双候选；支持超时换人、持久恢复、签名动态注册/下线、停止后续委派与独立业务复算。预算和链上金额使用整数/十进制字符串。

## 构建和测试

```shell
python manage.py build
python manage.py test-integration
python manage.py test-contract
python manage.py run-data
python manage.py run-travel
python manage.py test-security
```

`test-security` 运行合约测试、部署本地测试合约、RPC 对抗用例和应用专项；请在独立测试环境使用。更细入口用项目虚拟环境：Windows 为 `.cache\venv\Scripts\python.exe`，Linux 为 `.cache/venv/bin/python`。

```shell
.cache/venv/bin/python tests/e2e/run_main_scenario.py --repeat 10
.cache/venv/bin/python tests/e2e/run_main_scenario.py --scenario travel_planning --browser
.cache/venv/bin/python tests/e2e/run_main_scenario.py --transport b-http-v1
.cache/venv/bin/python tests/e2e/run_platform_acceptance.py
pnpm --dir apps/web run test:browser
```

普通 browser smoke 中未启动真实服务时的 live SKIP 不算通过；`--browser` 入口会实际启动服务与链。新日志写入被忽略的 `experiments/raw`，汇总与图写入 `experiments/results`。

## Docker

```shell
docker compose run --build --rm verify
```

该命令从源码构建独立环境，运行合约、RPC 安全、Python、应用专项、真实浏览器，以及 SDK/B HTTP 下的数据分析和旅游 E2E。基础镜像固定 digest。首次需联网下载依赖；新生成的原始证据和汇总挂载回本机 experiments 目录。该 Compose 服务用于验证，持续交互演示使用 `manage.py dev`。

## 自定义角色与 B HTTP

自定义 runtime 配置参考 `project.json`。`managedRoles` 可只启动指定本地角色，其余角色配置远端地址和公开钱包；真实私钥从对应环境变量读取。部署后执行 `manage.py configure --config <配置>`、`approve --amount <金额> --config <配置>`、`start --config <配置>`。`manage.py check` 验证链、合约、签名域、策略与服务身份；`manage.py schema` 导出配置和协议 Schema。

默认 `runtime.serviceTransport` 为 `a2a-v1`。设置 `b-http-v1` 使用原 B Card、RFQ、`/quotes`、`/tasks/send` 和 snake_case 消息，支持完整 managed 服务。不同传输使用独立 runtime/部署目录。

## 可选 Besu

保留五节点 QBFT 配置：`python scripts/module_c.py besu-init` 后使用 `docker compose -f infra/docker-compose.yml up -d`。默认 RPC 为 `127.0.0.1:8547`，chainId=1337。须先核对已有节点数据、端口及 genesis，不覆盖正在使用的网络。此次统一业务完整验收使用 Anvil；Besu 节点健康不等于业务完整验收。
