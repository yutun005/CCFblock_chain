# AgentFlow Pay 测试报告（Dmodule 集成验证）

## 1. 范围与结论

本报告记录 `Dmodule` 将 A 应用接到 C 的 DASC v1 合约接口后的验证情况。报告中的测试状态来自本分支实际执行结果；Cmodule 独立运行的结果不作为本分支端到端通过证据。

当前 Dmodule 采用 C 合约的 `TaskConfig`、EIP-712 布尔 `verdict`、`paymentToken()`、`expireTask(jobId, taskId)`、钱包级 `withdraw()` 和 `withdrawRefund(jobId)`。A 的任务规划、调度、A2A、成果验证与页面保留。C 合约没有链上 `planHash` 和 `requestStop`：任务需求哈希在链上逐任务核对；停止后续委派是本地调度状态，已接受任务仍可完成。钱包级提款事件没有 `jobId`，不在页面分摊到单个 Job。

## 3. 测试数据与方法

集成接口检查使用仓库中的 C `TaskEscrow.sol` 和 A `app.py` / `web.tsx`；检查 Solidity 函数、任务配置 tuple 顺序、EIP-712 `verdict` 类型、后端调用名称及前端账本文案。该检查不需要外部 RPC 或密钥。

链上安全、正常端到端、浏览器、恢复和性能测试必须由本分支的实际运行产生原始记录。没有日志和回执时标记为 `SKIP`，不引用其他分支的独立演示结果，也不推算或填写成功率、Gas 和耗时。
