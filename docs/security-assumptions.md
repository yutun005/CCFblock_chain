# 安全假设

1. 支付 token 为固定、无手续费、无重基准的标准本地测试 ERC-20。忽略外部意外转入对会计等式的影响。
2. owner、Agent、coordinator、verifier 的私钥未泄漏；本地演示使用随机生成的独立账户。
3. 授权验证者诚实执行创建时约定的客观规则。恶意验证者签名可导致坏结果获付款，SEC-30 记为 LIMITATION。
4. 平台管理员的验证者/中继授权受信。Job owner 选择自己的 coordinator。
5. RPC 连接配置正确，节点按 EVM 与 QBFT 规则执行；链 ID 不等于可信身份认证。
6. B 独立完成 Agent 服务端点与钱包的挑战绑定。仅声明钱包不充分，C 无法检查某个 URL 背后的经营主体。
7. 链下验证需读取与 resultHash 一致的原始字节，验证策略版本和 requirementHash 已统一。
8. 固定 Job 到期后资金可由 permissionless expire/finalize 收尾；owner 仍需主动领取退款。
9. 同一主机上的五个容器仅模拟多节点；不证明多组织独立运维、物理故障隔离或公网安全。
10. 演示使用无价值测试单位，不进行主网交易；赛事关于“发币”的解释由团队单独确认。

确认策略：本地 Anvil 和 Besu QBFT 默认等待 1 个成功回执，并核对回执区块哈希。公开网络不属于当前默认交易白名单，需要额外配置确认策略及重组恢复测试。
